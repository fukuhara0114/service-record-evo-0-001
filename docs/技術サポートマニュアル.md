## 2. システムの概要

修理・校正などの **サービス案件**、**貸出機**、**保守契約** を扱う社内 Web アプリケーション。

主な業務:

- 案件の受付（Intake）。PDF / 画像の取込、OCR、既存案件への紐づけ
- 案件一覧・詳細（Admin / Engineer / Invoice / Logistics など役割別）
- 貸出機マスタ、貸出予約、カレンダー、申請 PDF
- 保守契約の検索・更新、証明書 / 認定票 PDF、更新案内メール下書き
- 撮影画像（カメラ / Gallery）の登録と案件紐づけ
- メール（Gmail IMAP 受信監視、SMTP 通知、Power Automate からの未登録メール Note）

エントリポイント:

| URL | 動作 |
|---|---|
| `/` | ログイン済みなら `/home`、未ログインなら `/login` |
| `/login` | ログイン画面（ユーザー名 + パスワード） |
| `/home` | ホームメニュー |
| `/up` | Laravel ヘルスチェック（ミドルウェア外） |

ホームは画面幅でメニューが変わる。

- デスクトップ: ServiceRecord / Admin / Intake / Engineer / Invoice / Logistics / Loaner / Contract / Gallery / Users（管理者のみ）/ 価格改定（特定ユーザーのみ）
- タブレット（768–1023px）: Gallery / カメラ / Logistics
- スマホ（767px 以下）: `/servicerecord/camera` へ自動遷移

## 4. 環境構成（開発 IIS / 本番 Apache）

### 4.1 方針

| 項目 | 開発 | 本番 |
|---|---|---|
| Web サーバー | IIS + URL Rewrite | Apache + `mod_rewrite` |
| 設定ファイル | `public/web.config` | `public/.htaccess` |
| PHP | IIS FastCGI 想定 | 【要確認】PHP-FPM 想定 |
| 公開ディレクトリ | 【要確認】サイトまたは仮想ディレクトリ | **DocumentRoot を `public/` にする** |
| 定期実行 | 【要確認】タスク スケジューラ | cron + `php artisan schedule:run` |
| フロントビルド | `npm run dev` または `npm run build` | `npm run build` の成果物を配置 |

開発マシン上のパス例（リポジトリ配置）:

`C:\inetpub\wwwroot\dev\git_test\service-record-evo-0-001`

【開発】IIS はサブディレクトリ配信の可能性がある。その場合 `.env` の `APP_URL` を実際の URL（末尾スラッシュなし）に合わせる。

【本番】Apache は `public/` を DocumentRoot にする。プロジェクトルートを公開すると `app/` や `.env` が外から見える。

### 4.2 Apache VirtualHost 例（【本番】【要確認】実ホスト名）

```apache
<VirtualHost *:443>
    ServerName example.example.com
    DocumentRoot /path/to/service-record-evo-0-001/public

    <Directory /path/to/service-record-evo-0-001/public>
        AllowOverride All
        Require all granted
    </Directory>

    ErrorLog ${APACHE_LOG_DIR}/service-record-error.log
    CustomLog ${APACHE_LOG_DIR}/service-record-access.log combined
</VirtualHost>
```

必要なモジュール: `mod_rewrite`。`.htaccess` が効くよう `AllowOverride All`。

PHP は 8.3 以上。よく使う拡張: `pdo_mysql`（または使用 DB の PDO）、`mbstring`、`openssl`、`fileinfo`、`gd`、`zip`。IMAP は PHP の `imap` 拡張ではなく、ライブラリがソケット通信する。

### 4.3 IIS（【開発】）

`public/web.config` が未登録 URL を `index.php` に Rewrite する。IIS の URL Rewrite モジュールが必要。

Vite の本番ビルドは `manifest.json` を `.vite` フォルダではなく `public/build/manifest.json` に出す（IIS がドット始まりフォルダを拒否するため）。`vite.config.js` の `build.manifest` を参照。

### 4.4 環境変数（`.env`）

雛形は `.env.example`。秘密の値はここに書かない。サポート時は **キー名の有無と意味** を確認する。

| キー | 用途 |
|---|---|
| `APP_KEY` | 暗号化・セッション。未設定だと起動不可 |
| `APP_URL` | 絶対 URL 生成。環境の公開 URL に合わせる |
| `APP_ENV` / `APP_DEBUG` | 本番は `production` / `false` |
| `DB_*` | データベース。example は sqlite だが、既存表名から実運用は MySQL 系の可能性が高い【要確認】 |
| `SESSION_DRIVER` | example は `database` |
| `QUEUE_CONNECTION` | example は `sync`（HTTP 内でジョブ即実行） |
| `CACHE_STORE` | example は `database` |
| `MAIL_*` | SMTP。Gmail ならアプリパスワード |
| `GMAIL_IMAP_*` | 受信監視。未設定時は `MAIL_USERNAME` / `MAIL_PASSWORD` を流用 |
| `POWER_AUTOMATE_API_KEY` | `/api/power-automate/*` の認証 |
| `GEMINI_API_KEY` / `GEMINI_MODEL` | Intake OCR |
| `XSRV_AUTH_URL` / `XSRV_API_KEY` | OCR / Sync SM 前の外部認証 |
| `CAPTURED_IMAGE_*` | 撮影画像の保存先・サイズ |
| `PDF_IMPORT_*` | ファイル取込フォルダと Ghostscript |
| `MSIP_*` | abroad Excel の秘密度ラベル |
| `PDF_TEMPLATES_DIR` など | PDF テンプレートパス上書き |

設定を変えたあとは、本番では次を検討する。

```bash
php artisan config:clear
php artisan cache:clear
```

本番で `config:cache` している場合は、`.env` 変更後に `php artisan config:cache` し直す。

### 4.5 書き込み権限が必要な場所

Apache / IIS の PHP 実行ユーザーが書けること。

- `storage/` 一式（`logs`、`framework/cache`、`framework/sessions`、`framework/views`）
- `bootstrap/cache/`
- 撮影画像ルート（既定は `storage/app/uploadedImage/` 配下の `image` と `thumbnail`）
- PDF 取込の inbox / converted / reference / work_temp / error（`.env` の絶対パス）

`work_temp` は **ローカルディスク必須**。UNC 共有上だと TCPDF が書けない（コードコメントおよび `config/pdf_import.php`）。

## 5. 認証と権限

### 5.1 ログイン

- 画面: `/login`（`app/Http/Controllers/Auth/LoginController.php`）
- 認証項目: `users.name` + `password`（メールアドレスではない）
- 成功後: `/home`
- ログアウト: `POST /logout`

セッションは Laravel 標準。`SESSION_DRIVER=database` のときは `sessions` テーブルが必要。

### 5.2 ユーザー表

テーブル `users`。主キー `userID`。`created_at` / `updated_at` なし。

主な列: `name`、`kanji_name`、`email`、`password`、`permission`、`laborID`、`receive_info`、`signature`、`EmployeeID`。

ユーザー管理画面 `/users` は `permission` が `administrator` または `admin` のときだけ開ける。

権限の選択肢（Users 画面）: `administrator` / `admin` / `limited` / `guest`。

ホームの表示制御:

- Admin / Users: `administrator` または `admin`
- 価格改定: ログイン名が `hfukuhara` のときのみ（`resources/views/home.blade.php`）

Engineer 一覧は、ログインユーザーの `laborID` に紐づく案件に制限する。

### 5.3 API 認証（ログイン以外）

| 経路 | 認証 |
|---|---|
| 大半の `/servicerecord/*` | セッション（`auth` ミドルウェア） |
| `POST /api/power-automate/email-notes` | ヘッダ `X-API-Key` または Bearer。値は `POWER_AUTOMATE_API_KEY` |
| Intake OCR / smsync 認可 | 上記セッションに加え、xsrv.jp の `auth.php?key=` が `status=success` |

`POWER_AUTOMATE_API_KEY` が空だと Power Automate API は 503。キー不一致は 401。

### 6.1 案件（Service Record）

テーブル `servicerecord`。主キー `orderID`。

`order_type`:

- `service` … 修理・校正など
- `loaner` … 貸出
- `waiting_list` … 貸出待ち

`loaner` / `waiting_list` は、専用フロー以外で `service` に落とさない（`ServiceRecord` モデルの保護）。

詳細画面はレイヤ分割された Vue コンポーネント（メモ、添付、部品、貸出、メール下書きなど）。

### 6.2 Intake

未登録ファイル一覧 → 案件種別選択 → 新規作成または既存案件へ紐づけ。ブランク作成（ファイルなし）もある。

操作の画面手順は `docs/Intake操作マニュアル.pdf`。

関連処理:

- アップロード: `POST /servicerecord/intake/upload`
- フォルダ取込: `POST /servicerecord/file-import/start` → `ProcessImportFilesJob`
- OCR: `POST /servicerecord/intake/ocr`（Gemini + xsrv 認証）

### 6.3 貸出（Loaner）

- 個体マスタ: `loanermaster002`（業務キー `loanerID`、版管理あり）
- 案件側: `servicerecord.order_type = loaner` と `loanerID`
- ステータス定数: `app/Support/LoanerStatusFlow.php`

代表ステータス:

| 値 | 意味 |
|---|---|
| 0 | 確保済み / 在庫 |
| 20 | 案件未登録 |
| 100 | 見積済み |
| 150 | 受注 |
| 200 | 貸出機出荷準備 |
| 201 | 貸出機出荷準備＿差戻 |
| 300 | 貸出機出荷準備完了＿起伝依頼 |
| 350 | （旧）出荷依頼。Logistics の service 側でも使用 |
| 385 | Invoice の MAPICS 最終 |
| 388 | 貸出中 |
| 393 | 返却 |
| 396 | 受け入れ確認中 |
| 399 | 完了前・予約確認 |
| 400 | 完了（マスタの currentStatus は在庫 0 に戻る） |

申請書 PDF は `LoanerApplicationPdfService`。テンプレート論理名 `loaner_application`（既定ファイル `template_loaner.pdf`）。

### 6.4 保守契約

テーブル `maintenancecontractmaster`。一覧・詳細・複製、証明書 PDF、認定票 PDF、更新案内メール下書き。

契約タイプは `maintenance_contract_type`。

PDF テンプレート: `maintenance_contract.pdf`、`certification_ticket.pdf`。探索パスは `app/Services/PdfTemplatePathResolver.php`（`storage/app/template`、`resources/pdf-templates` など。Apache で DocumentRoot が `public/` の配置差も吸収）。

### 6.5 撮影画像

メタデータは `captured_image`。実ファイルは `CAPTURED_IMAGE_ROOT`（相対なら `storage/app/uploadedImage`）の `image/` と `thumbnail/`。

配信は認証付き URL のみ。

- `/servicerecord/camera/image/{fileName}`
- `/servicerecord/camera/thumbnail/{fileName}`

### 6.6 添付ファイル

テーブル `attachedfiles`。`content` 列に本体（base64 等）を持つ。未紐づけは `associatedID = -1`（取込の既定）。

EML のプレビュー、添付取り出し、返信ドラフトあり。

## 8. 外部連携

### 8.1 Gmail SMTP（送信）

用途: システム通知、担当アサイン通知、差戻通知、通電確認。

確認コマンド:

```bash
php artisan mail:test you@example.com
php artisan mail:notify {users.name} --subject="件名" --body="本文"
```

`MAIL_MAILER=smtp`、`MAIL_HOST=smtp.gmail.com`、ポート 465（smtps）または 587。パスワードは Google のアプリパスワード。

関連クラス:

- `app/Mail/SystemTestMail.php`
- `app/Services/Gmail/UserNotificationMailer.php`
- `app/Services/Gmail/AssignNotificationMailer.php`
- `app/Services/Gmail/RemandNotificationMailer.php`

### 8.2 Gmail IMAP（受信）

`gmail:poll-inbox` が INBOX を読み、Outlook deeplink を抽出して保存する。

- 設定: `config/gmail.php`、`.env` の `GMAIL_IMAP_*`
- カーソル: `gmail_imap_cursors.last_uid`
- 初回は `GMAIL_IMAP_INITIAL_LOOKBACK_DAYS`（既定 7 日）分を遡る
- ログ: `storage/logs/gmail-poll-inbox.log`（スケジューラの標準出力）および `storage/logs/laravel.log`

手動:

```bash
php artisan gmail:poll-inbox
php artisan gmail:poll-inbox --dry-run
```

### 8.3 Power Automate

`POST /api/power-automate/email-notes`

ヘッダ: `X-API-Key: {POWER_AUTOMATE_API_KEY}`

ボディ例の項目: `mailLink`（必須）、`subject`、`from`、`to`、`cc`、`date`、`bodyPreview`、`whoWrote`。

同じ `mailLink` はハッシュで重複排除し、既存なら 200、新規なら 201。

### 8.4 Gemini OCR

Intake で添付を読み取り、案件フィールド候補を返す。

- `GEMINI_API_KEY`、`GEMINI_MODEL`（既定 `gemini-2.5-flash`）、`GEMINI_TIMEOUT`
- 実装: `app/Services/GeminiOcrService.php`
- 事前に `XsrvAuthService` が成功していること

### 8.5 xsrv.jp 認証（Sync SM / OCR）

`XSRV_AUTH_URL` に `key=` を付けて GET。JSON の `status=success` が必要。

失敗時は OCR も smsync 認可も 403。メッセージ例: 「このシステムを利用する権限がありません、または有効期限が切れています。」

### 8.6 Ghostscript（PDF 取込）

PDF を FPDI 向けに互換変換する。パスは `PDF_IMPORT_GHOSTSCRIPT_PATH`。

- 【開発】Windows 例: `C:/Program Files/gs/gs10.04.0/bin/gswin64c.exe`
- 【本番】Linux なら通常 `gs`。【要確認】インストール有無とパス

未設定または実行ファイルが無いと、PDF はそのまま登録し、ログに警告を出す。

### 8.7 Microsoft Purview ラベル

abroad Excel 出力時。`MSIP_PUBLIC_LABEL_ID` / `MSIP_SITE_ID`。Public ラベル付き xlsx の `LabelInfo.xml` 由来。

## 9. 定期処理とジョブ

### 9.1 Laravel スケジューラ

`routes/console.php`:

- コマンド: `gmail:poll-inbox`
- 間隔: 5 分
- `withoutOverlapping()`
- 出力: `storage/logs/gmail-poll-inbox.log`

スケジューラ自体は **OS 側で 1 分ごとに** `php artisan schedule:run` しないと動かない。

【本番】cron 例:

```cron
* * * * * cd /path/to/service-record-evo-0-001 && php artisan schedule:run >> /dev/null 2>&1
```

【開発】Windows タスク スケジューラで同等を登録しているかは【要確認】。

### 9.2 ファイル取込ジョブ

`App\Jobs\ProcessImportFilesJob`

起動: ログインユーザーが `POST /servicerecord/file-import/start`。

動作概要:

1. inbox を走査
2. PDF は Ghostscript で互換化（可能な場合）、画像は JPEG 化など
3. `attachedfiles` に登録（既定 `associatedID = -1`）
4. 成功ファイルは converted、失敗は error、参照ファイルは reference（UUID 名）

`QUEUE_CONNECTION=sync` のときは HTTP リクエスト内で実行する。`queue:work` は不要。PHP / IIS / Apache のタイムアウトに注意（ジョブ timeout 600 秒）。

同時実行は Cache ロック。実行中の再起動は HTTP 423「現在他のユーザーが処理中です」。

inbox が空なら何もせず終了。

### 9.3 キューワーカー

`.env.example` は `sync`。`database` や `redis` に変えた場合は `php artisan queue:work` が別途必要。サポート時は必ず `QUEUE_CONNECTION` を確認する。

## 10. ログとトラブルシュート

### 10.1 見る場所

| 対象 | 場所 |
|---|---|
| アプリ | `storage/logs/laravel.log` |
| Gmail ポーリング（スケジューラ出力） | `storage/logs/gmail-poll-inbox.log` |
| 【本番】Apache | VirtualHost の ErrorLog / CustomLog【要確認】 |
| 【開発】IIS | IIS のサイトログ、PHP FastCGI の stderr【要確認】 |
| ヘルス | `GET /up` |

ログレベルは `LOG_LEVEL`。既定チャネルは `stack` → `single`。

### 10.2 よくある切り分け

**画面が白い / Vite アセット 404**

- 本番で `npm run build` 済みか、`public/build/manifest.json` があるか
- `APP_URL` が実際の公開 URL と一致しているか
- 【開発】`npm run dev` が落ちていないか

**ログインできない**

- `users.name` でログインしているか（メールではない）
- `APP_KEY`、セッション用テーブル、`storage/framework/sessions` の権限
- HTTPS 終端と `SESSION_SECURE_COOKIE` / `SESSION_DOMAIN`

**Intake の OCR が 403**

- `XSRV_AUTH_URL` / `XSRV_API_KEY`
- 外部 `auth.php` の有効期限
- サーバーから xsrv.jp へ HTTPS 出られるか

**OCR が 422 / 500**

- `GEMINI_API_KEY`
- タイムアウト（`GEMINI_TIMEOUT`、PHP `max_execution_time`）
- 対象ファイルの `attachedfiles.content` が空でないか

**メールが送られない**

- `php artisan mail:test`
- `MAIL_MAILER` が `log` のままだとファイルに出るだけ
- Gmail アプリパスワード、2 段階認証

**Gmail 受信が溜まらない**

- cron / タスクが `schedule:run` しているか
- `php artisan gmail:poll-inbox` を手動実行してエラーを見る
- IMAP 資格情報、`gmail_imap_cursors` の UID が異常に進んでいないか

**ファイル取込が進まない**

- inbox パスが実在し、PHP から読めるか
- Ghostscript パス（Windows の `.exe` を Linux に残していないか）
- 423 が続く → ロック残留。Cache（DB）のロック、または他プロセス実行中
- UNC パスを `work_temp` にしていないか

**PDF テンプレートが見つからない**

- `storage/app/template/` または `resources/pdf-templates/` にファイルがあるか
- `PDF_TEMPLATES_DIR` / 個別 `PDF_TEMPLATE_*`
- エラーメッセージに探索パスが列挙される

**Power Automate が 401 / 503**

- 503: キー未設定
- 401: ヘッダ不一致。`X-API-Key` を送っているか

**撮影画像が出ない**

- `storage/app/uploadedImage/image` にファイルがあるか
- ログインセッション付きで画像 URL を開いているか（直リンクは認証必須）

### 10.3 調査用コマンド

```bash
php artisan about
php artisan config:show app.url
php artisan route:list
php artisan test
```

設定キャッシュを疑うとき:

```bash

php artisan route:clear
php artisan view:clear
```

## 11. 開発・ビルド・デプロイ

### 11.1 ローカル（【開発】IIS）

依存関係:

```bash
composer install
npm install --ignore-scripts
```

`.env` を用意し `php artisan key:generate`。DB は既存業務 DB を指す想定（sqlite の example のままでは業務表が無い）。

フロント:

```bash
npm run dev      # 開発サーバ
npm run build    # 本番相当の静的ビルド
```

一括セットアップスクリプト（`composer.json` の `setup`）もあるが、migrate が既存 DB に与える影響は環境ごとに確認する。

### 11.2 本番デプロイ（【本番】Apache）【要確認】手順の詳細

コードから言える最小セット:

1. コードを配置（Git pull など）
2. `composer install --no-dev --optimize-autoloader`
3. `npm ci`（または `npm install`）と `npm run build`
4. `.env` を本番値に（`APP_DEBUG=false`、`APP_ENV=production`、Apache 用パス）
5. `storage` と `bootstrap/cache` の権限
6. DocumentRoot を `public/`
7. `php artisan migrate` は **レガシー表がある本番では慎重に**。必要なものだけ
8. `php artisan config:cache` / `route:cache` は運用方針に従う
9. cron で `schedule:run`
10. Ghostscript、PDF 取込フォルダ、撮影画像ディレクトリを Linux パスに直す

IIS 用の `web.config` は Apache では使わない。Apache は `public/.htaccess`。

Windows 専用パスが `.env.example` に残っている項目（Ghostscript、`C:/inetpub/...` の取込フォルダ）は、本番では必ず置き換える。

### 11.3 フロントの注意

Inertia ページは `resources/js/pages/`。ビルド成果物は `public/build/`。ビルドせずに `APP_ENV=production` で開くとアセットが欠ける。

## 12. 既知の注意点

- `README.md` は Laravel 雛形のまま、または Git コンフリクトマーカーを含む。運用説明としては使わない。本ファイルを正とする。
- ホームの「価格改定」はユーザー名ハードコード（`hfukuhara`）。権限モデルとは別。

- 日本語 PDF フォントは `storage/fonts/`（BIZ UDGothic、Noto Sans CJK など）と `JapanesePdfFontResolver`。
- テストは `tests/Unit` が中心（Loaner フロー、価格版、Outlook deeplink など）。`php artisan test`。
